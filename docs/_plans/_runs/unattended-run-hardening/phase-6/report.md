## Design
Wave: ready phases lowest first, greedy while room (max 3) and `Files:` fences do not overlap; no valid `Files:` line means alone; a wave of 1 uses the serial loop. Fence convention: none existed, so a `Files:` line under the phase heading (comma-separated plain relative paths, no glob, no `..`); neither convention doc edited; the planner trusts it, a stray implementer is caught only by a merge conflict. Worktrees beside the repo `<repo>-lane-<ID>-p<N>`, branch `at-lane/<ID>-p<N>`. Each lane has its own Runner and a private copy of state.md never read back. Lock: the integration Runner holds the run lock; only the driver thread writes state.md, ticks the task file, merges, one bookkeeping commit per wave. Implementer commit in a lane: must_not_have_committed raises, lane parks; before a merge the driver requires a clean worktree and exactly one commit on the lane branch. Merge `--no-ff`; conflict → `git merge --abort`; red check → `git reset --keep <pre>`; either parks the lane with path and branch in a Note:. One Stage: both wave review; a failure stops the run (exit 1) with the phases kept merged. Rerun after a kill: lane path derived from id and phase and checked against `git worktree list`; a clean lane with nothing unmerged is recreated; one with work is reported, row parked, nothing deleted.
